# A02:2025 - Security Misconfiguration

## Case 01: Exposed Metrics

### Краткая информация

- **Приложение:** OWASP Juice Shop `20.3.0`
- **Категория:** A02:2025 - Security Misconfiguration
- **Тип:** Открытый служебный эндпоинт
- **Связанный термин:** Information Disclosure / Missing Hardening
- **Состояние аутентификации:** доступ анонимный, без токена и cookies
- **Результат:** раскрытие версий, состояния рантайма и бизнес-показателей
- **Среда:** локальный учебный стенд

---

## 1. Описание

Security Misconfiguration возникает, когда приложение развёрнуто с небезопасными
настройками: включена функциональность, которая не нужна в продуктивной среде,
или не включена защита, которая должна быть.

В данном кейсе приложение публикует служебный эндпоинт метрик, предназначенный
для системы мониторинга. Эндпоинт доступен без аутентификации: любой, кто знает
адрес, получает данные о работе приложения.

Получение доступа не требует формирования специального запроса. Достаточно
обратиться по адресу обычным `GET`. Именно поэтому дефект относится к A02,
а не к Injection: входные данные не влияют на результат, отличается только
запрошенный ресурс.

От A01 (Broken Access Control) кейс отличается тем, что раскрываемый ресурс
не принадлежит ни одному пользователю. У него нет владельца, чьи права можно
нарушить: такой эндпоинт не должен быть доступен извне вообще никому.

## 4. Разведка

### 4.1. Поиск в клиентском коде

Первым шагом выполнен поиск строк `metrics`, `prometheus` в исходниках фронтенда
(DevTools, вкладка **Sources**). Совпадений не найдено.

Результат закономерен: вкладка **Sources** показывает только то, что загрузил
браузер, то есть клиентскую часть приложения. Экспортёр метрик - серверный
эндпоинт для системы мониторинга, фронтенд к нему не обращается. Значит искать
его нужно перебором серверных путей, а не анализом клиентского кода.

### 4.2. Определение ответа на несуществующий путь

Перед перебором необходимо узнать, как сервер отвечает на неизвестный адрес.
Запрошен заведомо отсутствующий путь:

```bash
curl -sI http://localhost:3000/wasaaaaap/
```

```http
HTTP/1.1 200 OK
ETag: W/"2700-1a18c4b1665"
Content-Type: text/html; charset=UTF-8
Content-Length: 9984
```

Ответ полностью совпадает с ответом на главную страницу:

| Признак | `/` | `/wasaaaaap/` |
|---|---|---|
| HTTP-статус | 200 | 200 |
| `Content-Type` | `text/html` | `text/html` |
| `Content-Length` | 9984 | 9984 |
| `ETag` | `W/"2700-1a18c4b1665"` | `W/"2700-1a18c4b1665"` |

Приложение отдаёт один и тот же `index.html` на любой неизвестный путь. Значит
код ответа `200` здесь ничего не означает, и фильтровать результаты перебора
нужно по размеру тела, а не по статусу.

### 4.3. Перебор серверных путей

```bash
ffuf -w /usr/share/seclists/Discovery/Web-Content/raft-medium-directories.txt \
     -u http://localhost:3000/FUZZ -mc all -fs 9984
```

Результат:

```text
metrics [Status: 200, Size: 26296, Words: 1031, Lines: 397, Duration: 126ms]
```

Фильтр `-fs 9984` отсекал ответы, совпадающие по размеру с заглушкой. Найденный
путь отличается от неё по размеру и типу содержимого, что и стало признаком
находки.

## 5. Анализ штатного запроса

Сначала проверено, как выглядит обычное обращение к приложению:

```http
GET / HTTP/1.1
Host: localhost:3000
```

```http
HTTP/1.1 200 OK
Content-Type: text/html; charset=UTF-8
Content-Length: 9984
```

Затем выполнен запрос к найденному пути:

```http
GET /metrics/ HTTP/1.1
Host: localhost:3000
```

```http
HTTP/1.1 200 OK
Content-Type: text/plain; version=0.0.4; charset=utf-8
```

Сравнение:

| Признак | `/` | `/metrics/` |
|---|---|---|
| Требуется аутентификация | нет | нет |
| `Content-Type` | `text/html` | `text/plain` |
| Что отдаётся | оболочка приложения | служебные метрики |

Оба запроса отличаются только путём. Никаких параметров, заголовков или
специальных значений в них нет.

`version=0.0.4` в `Content-Type` - это версия формата экспозиции Prometheus,
а не версия приложения. Не следует путать её с `20.3.0`.

### 6.3. Чего в ответе нет

Проверялось, раскрывается ли время ответа сервера:

```bash
curl -s http://localhost:3000/metrics/ | grep -iE 'duration|latency|response_time'
```

Совпадения есть, но обе метрики измеряют другое:

| Метрика | Что измеряет | Почему это не время ответа |
|---|---|---|
| `juiceshop_startup_duration_seconds` | длительность задач при старте | значение выставляется один раз при запуске |
| `nodejs_gc_duration_seconds` | длительность пауз сборки мусора | это работа сборщика мусора, а не обработка запроса |

Вывод: метрики времени ответа в экспортере нет. Ближайший к отзывчивости
показатель, который действительно раскрывается, - задержка event loop
(`nodejs_eventloop_lag_*`).

## 7. Механика уязвимости

Библиотека-экспортёр внутри приложения собирает метрики и отдаёт их по HTTP
по пути, заданному в конфигурации. Путь не является секретом: он определён
конвенцией инструментов мониторинга, чтобы скрейпер мог найти эндпоинт
без ручной настройки.

Маршрут зарегистрирован без проверки аутентификации, а на периметре нет правила,
ограничивающего доступ сетью мониторинга. Оба ограничения отсутствуют
одновременно, поэтому единственной защитой остаётся незнание адреса.

Что даёт раскрытие:

```text
1. Версии компонентов      -> подбор известных уязвимостей под конкретный стек
2. Аптайм и ресурсы        -> оценка запаса прочности и момента перезапуска
3. Задержка event loop     -> понимание, как система реагирует на нагрузку
4. Счётчики по кодам       -> видно, как сервер отвечает на запросы
5. Бизнес-показатели       -> сведения о клиентах и оборотах без авторизации
```

Отдельно стоит отметить счётчики `http_requests_count`. Они только растут,
и их приращение можно наблюдать. Это даёт обратную связь при слепых попытках:
если после запроса увеличился счётчик `5XX`, значит запрос дошёл до обработчика
и вызвал сбой; если не изменился - запрос отклонён раньше. Так атакующий
понимает, попадает ли он в цель, не видя ответа напрямую.

Ожидаемое безопасное поведение:

```text
1. Служебные эндпоинты не публикуются во внешний контур.
2. Доступ к ним ограничен сетевой политикой.
3. Дополнительно - авторизация с отдельной сервисной ролью.
4. Раскрываемый набор данных минимален: без версий и бизнес-показателей.
```

## 8. Корневая причина

Причина не в одной ошибке, а в отсутствии проверки конфигурации при выпуске:

```text
1. Экспортёр метрик включён по умолчанию и не выключается для прода.
2. Маршрут регистрируется без политики авторизации.
3. На периметре нет правила, закрывающего служебные пути.
4. Ни один шаг релиза не проверяет, какие служебные пути отвечают извне.
```

Первопричина: конфигурация не является проверяемым артефактом релиза.
Функциональные тесты такой дефект не находят - он виден только при проверке
периметра снаружи.

## 9. Примеры реализации на C#

Примеры уязвимой и защищённой конфигурации аналогичного приложения
на ASP.NET Core вынесены в папку code-example:

- [Уязвимая конфигурация](./code-example/vulnerable-configuration.cs)

- [Защищённая конфигурация](./code-example/secure-configuration.cs)

Эти файлы не являются исходным кодом OWASP Juice Shop. Они показывают, что
в ASP.NET Core конфигурация - это код: содержимое `Program.cs` определяет,
какие middleware и эндпоинты попадут в продуктовую сборку.

Уязвимый пример регистрирует метрики и служебные эндпоинты безусловно, вне
зависимости от окружения.

Защищённый пример показывает:

- включение метрик только в окружении разработки;

- авторизацию на служебных эндпоинтах;

- включение подробной диагностики только вне продуктивного окружения.

## 11. Итог

Подтверждено, что эндпоинт метрик доступен анонимно и отдаёт версии компонентов,
состояние рантайма, счётчики запросов и агрегированные бизнес-показатели.
Доступ получен без учётной записи, одним запросом `GET`, без формирования
специального входного значения.

Кейс закрывается одним изменением конфигурации: служебный эндпоинт исключается
из внешнего контура, доступ к нему переносится в сеть мониторинга и
дополнительно закрывается авторизацией.

Наиболее значимое следствие - не сам факт раскрытия данных, а то, что счётчики
дают атакующему обратную связь о реакции системы на его запросы.

```text
A02:2025 - Security Misconfiguration
Information Disclosure
Missing Hardening
Unauthenticated Operational Endpoint
```

## 12. Ограничения теста

Тест выполнялся только против локального экземпляра OWASP Juice Shop версии
`20.3.0`, запущенного в контролируемой лабораторной среде. Проверялся только
эндпоинт метрик и только факт анонимного доступа к нему. Другие служебные пути
и другие подтипы misconfiguration в рамках данного кейса не проверялись.

Воздействие на реальные системы и данные отсутствует.
